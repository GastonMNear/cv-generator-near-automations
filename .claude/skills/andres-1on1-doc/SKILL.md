# Andrés 1:1 running doc entry

Since Daniel left (Oct 2026), Gaston reports directly to **Andrés Bahamon (VP Marketing)**,
in a weekly 1:1 on Mondays. Andrés keeps a running Google Doc and asked Gaston to set the
agenda in it (Oct 5). The entry holds what's worth 1:1 time: things Andrés should know
about, decide on, unblock or give an opinion on.

**This is not a status report.** Progress, metrics and what's done go in the end-of-week
Slack update (`weekly-slack-update`). Gaston's feedback (Oct 19): the first draft listed
every status item, with audit counts, owners and caveats, and he cut it to five
discussion items. Andrés already gets the status in Slack, so repeating it here wastes
the meeting.

## What goes in

- **New opportunities**, e.g. a new tool or data source: what it is, what we'd use it for,
  and what testing would tell us.
- **Priorities / what's next**: the few things Gaston is focused on and why.
- **Concerns**: something that could go wrong, framed with the actual risk.
- **Ideas / proposals**: process or strategy changes Gaston wants Andrés's view on.
- **Asks**: budget, tools, subscriptions, headcount, or decisions only Andrés can make.
- **One-line status only when it leads somewhere**, e.g. "Chili Piper: Paz is finishing the
  router; then we update the hard follow-up copy."
- Optionally a "**Tasks for <person> to support Gasti with**" block.

Leave out metrics, experiment results, campaign IDs, record counts, routine ownership,
every meeting's action items, and anything unconfirmed.

## Workflow

1. **Read last week's entry** in `Near Work Partner/logs/andres-1on1/`. Follow up on things
   Gaston said would happen ("finished by Tuesday") only if they still need Andrés. Don't
   repeat items that are done and unremarkable.
2. **Gather the week** (follow `obsidian-wiki`, `wiki/hot.md` first): meetings in
   `wiki/meetings/` since last week's entry (TLDR and Action Items), tasks created or
   updated in `wiki/tasks/`, and `logs/`. Suggest `fathom-task-sync` if meetings look
   missing. Look for decisions that need Andrés, new options, risks and blockers. Skip
   routine progress.
3. **Ask Gaston what's not in the vault.** The best items often come only from him. On
   Oct 19, Moltsets, the lead-overlap concern and the "cohesive outbound engine" idea were
   all missing from the vault. Ask this alongside the draft ("Anything new this week I
   don't have, like tools, concerns or ideas?"), not before it.
4. **Read [references/examples.md](references/examples.md)** and draft to match its level.
5. **Save** Gaston's final version (not your draft) to
   `Near Work Partner/logs/andres-1on1/YYYY-MM-DD.md` once he confirms or pastes it.
   That's how next week knows what was already raised. If he rewrote a lot, add the
   lesson to `references/examples.md`.

## Shape and voice

- A date header (`Oct 19`), then **~4–6 top-level bullets**, with sub-bullets only for
  use cases or the "why".
- First person, Gaston's casual voice ("I'm worried about…", "I think adding this makes
  sense…"). Plain words. The reason it matters goes in a clause, not a paragraph.
- Lead each bullet with the topic (`HireBase …`, `Chili Piper links: …`) so it scans.

## Output

The draft goes in a plain block he can copy, with no vault links or Fathom timestamps.
Below it, a short "before you paste" list: the vault question from step 3, anything you
couldn't confirm, and sensitive items you left out on purpose (hearsay, people/staffing).
Gaston decides whether those go in.
